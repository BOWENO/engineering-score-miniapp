# 架构与领域边界

## 模块

- `auth`：微信登录、令牌、员工身份绑定。
- `organization`：用户、组织树、角色绑定及数据范围。
- `task`：每日任务生成、提交与校验。
- `scoring`：规则版本、积分规则、不可变积分事件和汇总缓存。
- `approval`：通用审核实例和动作。
- `settlement`：预结算、D级、强制分布、快照与发布。
- `publicity`：公示白名单和匿名策略。
- `appeal`：员工申诉与复核。
- `attachment`：私有凭证、哈希、签名访问。
- `audit`：操作日志与 request_id 追踪。

## 一致性边界

积分事件写入、审核状态变化和汇总更新在同一数据库事务完成。`score_event` 是账本真源，`score_summary` 是可重建缓存。已生效事件不更新、不删除；纠错使用反向事件和新事件。

## API约定

- 前缀：`/api`
- 编码：UTF-8 JSON
- 认证：短期 access token
- 幂等：写请求携带 `Idempotency-Key`
- 并发：资源携带 `version`，冲突返回 409
- 追踪：响应头与响应体返回 `request_id`

## 身份认证

- 小程序生产环境调用 `wx.login`，服务端通过微信 `code2Session` 换取 `openid`。
- `openid` 必须预先绑定有效员工档案；未绑定返回 `IDENTITY_NOT_BOUND`，不会自动创建生产账号。
- 服务端只保存访问令牌 SHA-256 摘要，明文令牌仅在签发时返回，默认两小时失效。
- `/api/auth/dev-login` 只在 `local` 和 `test` profile 存在，生产环境不可访问。

## 凭证与审核

- 凭证保存在S3兼容私有桶，服务端校验类型、大小和SHA-256，不向客户端暴露对象存储地址。
- 附件读取同时校验业务角色与组织范围；平台系统管理员不能以配置权限查看业务凭证或代审。
- 审核动作使用乐观锁并记录动作历史和操作日志；通过后在同一数据库事务内写入积分事件和汇总。

## 规则治理

- 系统管理员创建规则草稿和维护技术配置，但不能完成业务审批。
- 部门经理检查业务内容并将版本推进到 `BUSINESS_APPROVED`，但不能执行系统发布。
- 系统管理员只能发布已经完成业务审批的版本；发布时退役上一发布版本。
- 每日任务和员工申报锁定规则版本ID，规则升级不重算或覆盖历史事件。

## 结算与公示

- 预结算读取月度汇总、确认D级名单、人员范围快照和明确规则版本，生成独立结算批次。
- D级不占S至C的分配名额；强制分布使用最大余数法处理比例取整。
- 自动比较无法打破的同分边界必须由部门经理填写理由后确认。
- 发布会创建新的不可变 `grade_snapshot`；申诉接受也不原地修改快照，后续更正通过新结算版本完成。
- 公示接口只返回姓名或匿名名、总分、排名和正式等级，不返回扣分原因、D级证据或申诉内容。
